بوسراج للألعاب — 11.0.2
دليل نشر المشروع الكامل

1) فك ZIP وافتح الطرفية داخل snake_pro_v11_2 حيث package.json وwrangler.jsonc.
2) استخدم Node.js 24، ثم نفذ بالترتيب:

npm ci --include=dev
npm run verify:release
node scripts/verify-worker-config.mjs
npm run check:cloudflare
npm run test:cloudflare
npx wrangler login
npm run deploy

الأمر deploy ينشر العامل والأصول كاملة. نشر public فقط لا يحدّث قوانين الغرف على السيرفر. في V11 انشر الواجهة وsrc معًا لتفعيل المتجر والمهمات وصلاحيات bosrag والثعبان المطوّر في الأونلاين. لا يلزم ترحيل جديد لهذا النمط؛ احتفظ بإعدادات العامل وترحيلاته الحالية.

اسم العامل المحفوظ في الحزمة: tahdia-online
ROOMS -> GameRoom
BOARD_ROOMS -> BoardRoom
QUICK_ARENA -> QuickArena

الحسابات تستخدم التفويض الداخلي في BOARD_ROOMS. لا يوجد احتياج إلى SOCIAL_USERS في هذه النسخة.
حافظ على migrations المنشورة v1 وv2 وv3-board-room-rename كما هي. أُضيفت في آخر القائمة:
v6-authoritative-quick-arena -> new_sqlite_classes: QuickArena
لا تحذف تاريخ migrations ولا تغيّر اسم العامل إذا كان هذا تحديثًا لنفس الخدمة. إن كان إعداد حسابك المنشور مختلفًا، حافظ على إعداداته السابقة وأضف binding والترحيل الجديد بعد آخر migration معتمد فيه.

ملاحظة تحديث حي:
يفضل إنهاء الغرف النشطة قبل تحديث الواجهة. العملاء القدامى لا يرسلون expectedVersion الجديد، لذلك اطلب إعادة تحميل الصفحة بعد نشر V11؛ ستُرفض حركاتهم القديمة بدل تكرارها. صفحة PWA تحتاج زيارة متصلة ليكتمل الكاش الجديد.

بعد النشر افتح /api/health. يجب أن تتضمن الاستجابة:
ok: true
online: true
quizOnline: true
boardOnline: true
quickOnline: true
socialOnline: true
version: "7.0.0"
release: "11.0.2"

فحص محرك الغرف بعد النشر:
افتح /api/board/health. يجب أن يعرض ok: true وengine: BoardRoom وrelease: 11.0.2.
BOARD_BINDING_MISSING يعني أن ربط BOARD_ROOMS مع BoardRoom غير موجود.
BOARD_ENGINE_OUTDATED يعني أن العامل أو محرك الغرف ما زال قديمًا.
BOARD_ENGINE_UNAVAILABLE يعني أن تشغيل المحرك فشل؛ راجع النشر والترحيلات وسجل العامل.
ROOM_INITIALIZATION_FAILED يعني فشل حفظ غرفة؛ يتراجع المحرك عن التهيئة ويمكن المحاولة مجددًا.
رقم الفحص في الرسالة يطابق السجل في السيرفر، ولا يتضمن مفاتيح الغرفة أو جلسات الحساب.

فحوص قبول على الموقع المنشور:
- حسابان منفصلان: تسجيل، صداقة، قبول، خصوصية ودعوة إلى غرفة.
- مباراة سريعة بين الجهازين حتى النهاية: نقاط متطابقة، رفض الإجابة بعد انتهاء الوقت، مكافأة واحدة بعد إعادة التحميل.
- الثعبان: أنشئ غرفتين، كلاسيك ومطوّرة؛ راقب شرط ٦ للدخول، ونرد المكافآت في ١٢ و٤٦ و٨٢، والحماية والنردين، ثم افصل الشبكة وأعد الاتصال وأعد المباراة إلى الانتظار.
- الجاكارو: أربعة متصفحات/جلسات، يد كل لاعب خاصة، اختيار ورقة وحجر، فوز الفريق بعد دخول ثمانية أحجار.
- الزهرة: انتظار اختيار الحجر ومنع إعادة الرمية، ثم فوز وإعادة جولة.
- المتجر: رصيد غير كافٍ، شراء واحد بالنقر المتكرر، مجموعة بقطع مملوكة، عرض ينتهي أثناء الشراء، ظهور التجهيز وآثار الحركة والاحتفال في اللعبة ومزامنته على الجهاز الثاني.
- المهمات: جولات مكتملة، استلام مرة واحدة، انتقال يوم الرياض والأسبوع، ونتيجة أونلاين موثّقة.
- bosrag: دخول بكلمة مروره المعتادة، كل المقتنيات مفتوحة، إدارة حساب آخر، عملات وخبرة وفتح مقتنيات، إيقاف وإعادة تفعيل وإنهاء جلسات، إعلان وإزالته، ورقم طلب ثابت عند انقطاع الاتصال.
- حساب لاعب آخر: لا يرى أدوات الإدارة ولا يستطيع استدعاء مساراتها. اسم ظاهر bosrag لا يمنح صلاحية.
- النتائج المحلية: أكمل جولة مع قطع الشبكة، أغلق وافتح الصفحة، ثم اتصل بالحساب نفسه؛ تأكد أن النتيجة تُضاف مرة واحدة.
- PWA: زيارة الصفحات متصلًا أولًا، ثم وضع الطيران؛ اختبر اللعب المحلي والأصوات والكاش.
- جرب Android وiOS واتجاهي الشاشة مع خيار تقليل الحركة.

Firebase القديم:
المواجهة السريعة الجديدة لا تستدعي Firestore. الملف firebase/firestore.rules يرفض وصول المتصفح إلى match_queue وmatches ويحتوي سياسة رفض افتراضية. راجع مجموعات مشروعك الأخرى وادمج قواعدها المقصودة قبل تطبيق الملف؛ ثم انشر قواعد Firestore من Console أو من مشروع Firebase المهيأ باستخدام:
firebase deploy --only firestore:rules --project YOUR_PROJECT_ID
هذه القواعد ليست منشورة ضمن أمر wrangler deploy.

تم التحقق من محاكاة السيرفر وDOM، ومن تشغيل workerd محليًا مع SQLite وWebSocket ومن تجهيز النشر عبر Wrangler dry-run. لم يُنفَّذ نشر إلى حساب Cloudflare أو اختبار متصفحات/أجهزة حقيقية في جلسة التسليم.

الخطأ المؤكد في الصورة: Exceeded allowed volume of requests in Durable Objects free tier.
الخطة المجانية تسمح بـ100,000 طلب يوميًا، وتحتسب استدعاءات HTTP وWebSocket والمؤقتات. تعود الحصة عند 00:00 UTC / 03:00 في السعودية. إذا بلغ الحساب حده، يلزم انتظار إعادة الضبط أو تغيير خطة Workers عبر حسابك في Cloudflare. التصحيح يقلل الهدر، ولا يرفع حدود الحساب.
تأكد من نشر src/index.js مع الواجهة؛ إصلاح المؤقتات على السيرفر هو الجزء الضروري، وليس مجرد تحديث الرسالة.
لا تحذف الغرف أو الحسابات ولا سجل migrations لمعالجة هذه الرسالة.
