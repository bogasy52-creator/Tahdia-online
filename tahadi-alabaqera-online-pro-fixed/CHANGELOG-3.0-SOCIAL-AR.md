# بوسراج 3.0 — Social Platform

هذا الإصدار يضيف طبقة اجتماعية كاملة فوق محركات الألعاب الحالية بدون تغيير قواعد اللعب الموثوقة أو تاريخ Durable Objects المنشور.

## الحسابات 👤
- إنشاء حساب باسم مستخدم فريد (3–20: أحرف إنجليزية/أرقام/شرطة سفلية).
- اسم عرض يدعم العربية.
- كلمات المرور مخزنة بصيغة PBKDF2-SHA256 مع Salt مستقل، ولا تُخزن كنص صريح.
- Sessions عشوائية طويلة، المخزن على السيرفر هو SHA-256 للسر فقط.
- حد أقصى 8 جلسات نشطة للحساب وانتهاء افتراضي بعد 30 يومًا.

## الأصدقاء 👥
- بحث مباشر باسم المستخدم وإرسال طلب صداقة.
- قبول/رفض الطلبات، حذف الصديق، الحظر وإلغاء الحظر.
- قائمة أصدقاء مع حالة Online/Offline وآخر ظهور.
- حد أقصى 100 صديق و100 طلب وارد للحساب.

## Presence & Realtime 🟢
- Durable Object جديد `SocialUser` لكل حساب.
- WebSocket مستقل للطبقة الاجتماعية باستخدام WebSocket Hibernation API.
- بيانات Session الحساسة تمر عبر `Sec-WebSocket-Protocol` ولا تدخل Query String.
- تحديث حالة الأصدقاء لحظيًا مع خيار إخفاء الظهور.

## دعوات اللعب 🎮
- إرسال دعوة مباشرة لصديق من لوبي:
  - تحدي العباقرة
  - جاكارو
  - سباق الـ100 / السلم والثعبان
  - الزهرة
- الدعوة تتحقق من أن الغرفة موجودة، تخص اللعبة المطلوبة، وما زالت في اللوبي.
- الدعوة صالحة 5 دقائق وتحتوي رابط دخول مباشر للغرفة.
- إعداد الخصوصية: الجميع / الأصدقاء فقط / لا أحد.

## الواجهة
- صفحة `/social` للحساب والأصدقاء والطلبات والإشعارات والخصوصية.
- زر الأصدقاء وشارة عدد الإشعارات في الصفحة الرئيسية.
- زر `👥 دعوة صديق` داخل لوبيات الألعاب الأونلاين.
- إذا كان المستخدم مسجلًا، يتم تعبئة اسم اللاعب تلقائيًا من الحساب.
- PWA App Shell مرفوع إلى `busraj-games-v14` ويخزن أصول Social الجديدة.

## Cloudflare
- Binding جديد: `SOCIAL_USERS -> SocialUser`.
- Migration جديدة Append-only: `v4-social-users`.
- تاريخ migrations السابق محفوظ كاملًا:
  - `v1 -> GameRoom`
  - `v2 -> BoardGameRoom`
  - `v3-board-room-rename -> BoardRoom`
  - `v4-social-users -> SocialUser`

## نظام التحديث الآمن
- تمت إضافة `.github/scripts/merge-worker-config.mjs`.
- تحديث ZIP القديم الذي لا يعلن Durable Objects يستمر في الحفاظ على `wrangler.jsonc` المنشور كما هو.
- تحديث يضيف Durable Object جديدًا لا يُقبل إلا إذا:
  - حافظ على كل migrations المنشورة بنفس الترتيب والمحتوى.
  - لم يحذف أو يغير أي binding منشور.
  - أضاف migration جديدة صريحة لكل binding/class جديد.
- أي محاولة لتقصير/إعادة كتابة تاريخ Cloudflare تفشل قبل النشر.
