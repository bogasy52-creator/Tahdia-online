# بوسراج للألعاب — الإصدار الاحترافي 2.2

منصة ألعاب عربية تعمل على Cloudflare Workers وDurable Objects. إصدار 2.2 يركز على **الاعتمادية، حماية الغرف، تحمل انقطاع الاتصال، وصحة قواعد اللعب** مع استمرار اللعب المحلي والأونلاين.

## الألعاب

### تحدي العباقرة — محلي
- 23 فئة و207 أسئلة من المحتوى الأصلي.
- نظام نقاط ومساعدات وزوم وأسئلة صوتية/صورية.
- نظام صوت موحّد للمؤقت والجولات والإجابات.
- تصعيد صوتي في آخر 10 ثوانٍ وتنبيه أقوى في آخر 5 ثوانٍ.

### تحدي العباقرة — أونلاين 1 ضد 1
- غرف من 6 أرقام وWebSocket لحظي.
- Durable Object مستقل لكل غرفة.
- 12 جولة بين الإجابة السرية والبازر والسرقة.
- السيرفر authoritative للبازر والنقاط وحالة الجولة.
- reconnect token لإعادة الاتصال بدون كشفه في رابط WebSocket.
- حماية من دخول الضيف كمضيف قبل منشئ الغرفة.
- مهلة 45 ثانية لانقطاع اللاعب في اللوبي، مع تنظيف المقعد أو نقل الاستضافة تلقائيًا عند الحاجة.
- الغرف تنتهي وتُنظف تلقائيًا بدل بقائها معلقة.

### السلم والثعبان
- 2 إلى 4 لاعبين محليًا أو أونلاين.
- لوحة 1–100 باتجاه متعرج.
- سلالم وثعابين وحركة متدرجة للقطع.
- الرقم 6 يمنح رمية إضافية، والوصول إلى 100 يحتاج رقمًا دقيقًا.
- في الأونلاين الرمية والحركة يحسمهما السيرفر.

### تحدي النرد
- 2 إلى 4 لاعبين محليًا.
- نمط «سباق النقاط»: استمر في الرمي أو ثبّت نقاطك قبل ظهور 1.
- نمط «أعلى رمية» بجولات قابلة للاختيار.
- مؤثرات رمي وحالة دور واضحة وشاشة فوز.

### الزهرة
- 2 إلى 4 لاعبين محليًا أو أونلاين.
- أربعة أحجار لكل لاعب.
- الستة لإخراج الحجر، وخانات أمان، وأكل الخصم، ومسار نهاية خاص بكل لون.
- إنهاء الحجر يحتاج رقمًا دقيقًا، والفائز أول من ينهي أحجاره الأربعة.
- في الأونلاين توجد مهلة قرار بعد الرمية ومعالجة تلقائية عند انقطاع صاحب الدور.

### جاكارو — نسخة بوسراج
- 4 لاعبين، فريقان: الأول + الثالث ضد الثاني + الرابع.
- أوراق لعب بدون جوكر، وتوزيع 4 / 4 / 5.
- A دخول أو 1/11، 4 للخلف، 5 لتحريك حجر مؤهل، **7 كاملة لحجر واحد أو قابلة للتقسيم**، J للتبديل، Q=12، K للدخول أو 13.
- شاشة خصوصية بين الأدوار في المحلي.
- في الأونلاين لا يرسل السيرفر لأي لاعب محتوى أوراق خصومه.
- فوز الفريق بعد إنهاء أحجار الشريكين الثمانية.

## تحسينات الأونلاين في 2.2 🔐
- منع استحواذ أول زائر على صلاحية المضيف بدون `hostKey` صحيح.
- نقل `hostKey` وreconnect token من Query String إلى WebSocket subprotocols.
- رفض طلبات API/WebSocket القادمة من Origin خارجي؛ لا يوجد `CORS *`.
- Rate limiting لإنشاء الغرف، فحص حالتها، ومحاولات WebSocket، مع تخزين Durable Object وفallback محلي.
- مهلة انقطاع 45 ثانية في اللوبي قبل تحرير المقعد.
- نقل الاستضافة تلقائيًا في اللوبي عند انتهاء مهلة المضيف المنقطع ووجود لاعب متصل.
- مهلة دور 60 ثانية في ألعاب اللوح، و25 ثانية لاختيار حركة الزهرة بعد الرمية، مع عداد مرئي متزامن مع وقت السيرفر.
- إعادة المباراة تعود إلى اللوبي وتطلب الجاهزية بدل بدء مباراة جديدة فورًا.
- زر الخروج في عميل ألعاب اللوح يحرر المقعد صراحةً في اللوبي.
- تنظيف صحيح للغرف المنتهية وعدادات Rate Limit المنتهية.

## الحماية وجودة الواجهة
- أسماء اللاعبين تمر عبر تنظيف في السيرفر، ويتم Escape لها قبل إدخالها في HTML المحلي والأونلاين.
- استجابات API تستخدم `nosniff` و`referrer-policy` المناسبة.
- التحقق من بروتوكول WebSocket `busraj-v1` قبل قبول جلسة اللعب.
- معالجة reconnect ومنع تكرار الحركة أثناء انتظار تحديث السيرفر.

## نظام الصوت
`public/assets/js/audio-manager.js` هو المصدر الموحد للصوت في المنصة:
- مؤثرات موجودة من النسخة الأصلية حيث تناسب الحدث.
- مؤثرات Web Audio خفيفة للحركة والنرد والأوراق والسلالم والثعابين والبازر.
- تحكم مستقل بالمؤثرات وصوت المؤقت والاهتزاز ومستوى الصوت.
- الإعدادات محفوظة في `localStorage`.
- فك حظر الصوت على الجوال بعد أول تفاعل من المستخدم.

## الواجهة وPWA
- الصفحة الرئيسية مركز ألعاب واحد باسم «بوسراج للألعاب».
- تصميم متجاوب للجوال والكمبيوتر.
- إعدادات صوت مشتركة.
- Service Worker cache v7 يسبق تخزين صفحات الألعاب والمحركات والأصوات الأساسية.
- صور الأسئلة الخارجية تُخزّن best-effort في الكاش لتقليل مشاكل ضعف/انقطاع الشبكة بعد تثبيت الـService Worker.
- Manifest محدث باسم المنصة.

## البنية التقنية
- Cloudflare Workers Static Assets للواجهة.
- `src/index.js` للـAPI وغرف تحدي العباقرة وغرف الألعاب اللوحية الأونلاين.
- Durable Objects + SQLite-backed storage: `ROOMS` للأسئلة و`BOARD_ROOMS` للألعاب اللوحية.
- WebSocket Hibernation API للتزامن اللحظي.
- محركات الألعاب مستقلة داخل `public/assets/js/engines/` حتى تبقى القواعد قابلة للاختبار بعيدًا عن الواجهة.

## الاختبارات
شغّل:

```bash
npm test
```

الحزمة الحالية تحتوي **32 اختبار Node** تشمل المحركات، الحماية، reconnect، صلاحية المضيف، Rate Limiting، وقواعد جاكارو.

للتحقق الشامل قبل النشر:

```bash
npm run verify
```

هذا يشغّل الاختبارات، يتحقق من روابط الملفات المحلية، ثم ينفذ Cloudflare dry-run عبر Wrangler.

## النشر على Cloudflare
من جذر المشروع:

```bash
npm install
npx wrangler login
npm run verify
npm run deploy
```

المشروع مضبوط على Worker الحالي في `wrangler.jsonc`. يجب نشر المشروع كاملًا وليس مجلد `public` وحده.

بعد النشر افحص:

```text
/api/health
```

والنتيجة المتوقعة تشمل:

```text
ok: true
online: true
quizOnline: true
boardOnline: true
version: "2.2.0"
```

> ملاحظة: فحص Wrangler dry-run يحتاج تثبيت `wrangler` من npm. إذا كانت بيئة العمل بلا اتصال، شغّل `npm install` ثم `npm run verify` على جهاز متصل قبل النشر.
